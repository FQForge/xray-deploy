# 入站、客户端与网络配置测试记录

测试日期：2026-10-25（America/Los_Angeles）。测试机使用用户提供的 IPv6 SSH 地址、22 端口，系统为 Debian 12 amd64、512 MB 内存，内核为 Xray v26.6.1。

## 配置、状态与交互

`tests/inbounds.sh` 已在本地及测试机通过。配置校验调用真实 Xray 内核，服务钩子在临时目录模拟成功和失败，不操作系统服务。

覆盖内容包括：保存空入站并保留监听端口；同端口添加多个独立客户端；入站及客户端启停；批量导出过滤停用客户端；改名、删除、监听端口和 NAT 地址修改；七种 SS 加密及 SS2022 AES 双密钥导出；SOCKS5/HTTP 账号特殊字符及重复账号拒绝；Reality 多 UUID 与诊断客户端选择；旧版单用户、多用户、混合加密 SS 和重复显示名称导入；保留原标签、地址和连接凭据。

还验证了自定义向导的输入顺序、创建后暂不添加客户端、五种协议快速创建、嵌套查看菜单，以及总览不输出凭据。核心校验失败、服务启动失败时，运行配置和入站管理数据保持原值。现有出站、路由和未受管入站在操作后保留；有路由引用的入站不能直接删除。

## 外部 IPv4 NAT 与 IPv6

用户指定可用 NAT 端口范围为 **30302–30310**。以下测试使用临时目录中的真实 Xray 服务端、独立的服务脚本和进程；从测试机外部启动真实 Xray 客户端连接，不覆盖系统服务配置。

| 入站 | 本机 / NAT 公网端口 | 客户端数 | 外部 IPv4 NAT | 外部 IPv6 |
| --- | --- | --- | --- | --- |
| SS，aes-256-gcm | 30303 | 2 | HTTPS、UDP DNS 通过 | HTTPS、UDP DNS 通过 |
| SS2022，AES256 多用户 | 30304 | 2 | HTTPS、UDP DNS 通过 | HTTPS、UDP DNS 通过 |
| VLESS + Reality | 30305 | 2 | HTTPS 通过 | HTTPS 通过 |
| SOCKS5 | 30306 | 2 | HTTPS 通过 | HTTPS 通过 |
| HTTP CONNECT | 30307 | 2 | HTTPS 通过 | HTTPS 通过 |

每种协议都逐个停用第一个客户端，验证其外部 IPv4 连接失败，同时第二个客户端继续正常访问 HTTPS。外部测试结束后停止临时服务，删除测试入站、客户端凭据和临时文件。

## 服务器内的真实连接

`tests/integration.sh` 使用 **30302** 端口依次验证，各协议完成后释放端口。测试配置只放行动态创建的本机 TCP/UDP 测试目标；系统配置的默认私有地址拦截保持原样。

四种普通 SS 加密和三种 SS2022 加密均已通过真实 TCP、UDP 与 IPv6 连接测试。支持多用户的六种加密还通过了两个客户端分别连接、停用一个后另一个继续连接的验证。SS2022 ChaCha20 使用单客户端模式。

SOCKS5/HTTP 通过双账号、IPv6、包含冒号、空格、`@`、`%` 的密码，以及停用账号拒绝连接测试。Reality 的本机双 UUID、IPv6、停用隔离和内置诊断均通过，外部结果见上表；创建时的真实 TLS/HTTPS 自检也通过。

## 出站、路由与负载均衡

同一台 NAT 测试机、Xray v26.6.1 上新增验证了 `tests/network.sh` 和 `tests/network-integration.py`。测试使用临时配置、独立进程及 **30303–30310** 端口，现有 SS 节点的 **30302** 端口留给正式服务。

状态测试覆盖：原有配置导入且不改运行配置；分享链接中的 IPv6、中文、特殊密码、七种 SS 加密、Reality 和传输参数；错误链接与 JSON 拒绝；批量选择、标签冲突和出站链引用重写；规则排序、启停、默认均衡组、删除保护；路由 JSON 导出再导入后的默认出口与规则顺序；重复规则提示；无效正则和运行服务重启失败时回滚；入站修改保留网络配置，停用规则仍保护被引用的入站。

真实流量测试通过：

| 功能 | 验证结果 |
| --- | --- |
| 出站链接导入 | SOCKS、HTTP、SS、SS2022、VLESS + Reality 的真实代理链和公共 HTTPS 握手通过，上游使用 IPv6 |
| 原生 JSON 导入 | VMess、Trojan 真实代理链通过，测试上游只监听临时回环端口 |
| SS 入站跨协议转发 | 转发到上述七类协议的出站均返回对应上游的 HTTP 标记 |
| 路由规则 | 域名、IPv4 网段、目标端口、来源入站、拦截、优先级、开关、默认直连通过 |
| 客户端分流 | 同一个 SS 入站的两个客户端按稳定身份分别走指定出站和默认出口 |
| 轮询 | 8 次请求中，两个成员各接收 4 次 |
| 随机 | 24 次请求覆盖两个成员 |
| 最低延迟与回退 | 选择较快成员；关闭该成员后切换；全部关闭后回退直连；恢复后重新选择较快成员 |

`tests/network-external.py` 还从独立机器通过实际公网 IPv4 NAT 映射和公网 IPv6 完成测试：30303 的轮询在两种地址上均为 4/4；30310 的 SS 入站转发到 SOCKS、HTTP、SS、SS2022、Reality、VMess、Trojan 出站均通过，两种地址都获得正确上游的 HTTP 响应。跨协议测试使用确定的 HTTP 目标，公共 HTTPS 握手覆盖范围见上表。
