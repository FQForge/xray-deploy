# Xray 中文节点管理工具

在 Linux 服务器上通过中文菜单管理 **入站、客户端、服务器出站、路由规则和负载均衡**，适用于公网 VPS、NAT 端口映射、IPv4 / IPv6 和动态 IP / DDNS 环境。

入站支持 **SS、SS2022、VLESS + Reality、SOCKS5、HTTP**。服务器出站可以使用当前 Xray 内核支持的协议，入站和出站的协议可以不同。

## 安装与运行

登录服务器后执行：

```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/FQForge/xray-deploy/main/install-xray-ss.sh)"
```

安装完成后自动打开菜单，以后输入 `xnode` 即可；普通用户使用 `sudo xnode`。首次创建节点时会安装 Xray 内核和所需依赖，默认内核为 **v26.6.1**。

Debian / Ubuntu 缺少 `curl` 时，先执行：

```bash
apt-get update && apt-get install -y curl
```

推荐使用 **Debian 12 / 13 或 Ubuntu 22.04 / 24.04**。脚本也适配 Alpine、Rocky / AlmaLinux / Fedora、openSUSE、Arch、Void、Gentoo 和 OpenWrt 的常见包管理与服务方式。CPU 架构须有对应的 Xray 官方 Linux 安装包，系统软件源须可用，Reality 连接检查需要 curl 支持 TLS 1.3。

服务管理支持 systemd、OpenRC、SysVinit、runit 和 procd；未识别到服务管理器时使用手动模式，需要自行安排开机启动。运行 `xnode check` 可查看当前系统的兼容性检查结果。

## 主菜单

| 序号 | 功能 | 用途 |
| --- | --- | --- |
| 1 | 快速创建节点 | 自动创建入站和首个客户端，生成连接信息 |
| 2 | 查看节点 / 复制链接 | 按入站和客户端查看链接、导出客户端出站 JSON，或批量显示链接 |
| 3 | 入站与客户端总览 | 查看名称、协议、端口和启用数量，不显示密码 |
| 4 | 入站与客户端管理 | 管理监听端口、连接地址、客户端及开关 |
| 5 | 服务器出站 | 从协议链接或 JSON 导入出口，管理和测试连接 |
| 6 | 路由规则 | 配置分流、默认出口、域名解析策略和嗅探 |
| 7 | 负载均衡 | 管理成员、策略、健康探测和故障回退 |
| 8 | 服务管理 | 查看状态、启动 / 重启、日志和 Reality 诊断 |
| 9 | 高级设置 | 自定义创建、内核版本、DDNS、系统检查和卸载 |

菜单输入 `0` 返回上级或退出。

## 入站与客户端

**入站**保存协议、监听端口、连接地址和传输设置，**客户端**保存各自的 UUID、密码或代理账号。一个入站中的客户端共享监听端口，可以分别管理凭据、名称和启用状态。

| 入站协议 | 加密 / 传输 | 客户端方式 | 需要放行 |
| --- | --- | --- | --- |
| SS | AES-128-GCM、AES-256-GCM、ChaCha20-Poly1305、XChaCha20-Poly1305 | 多客户端，各自使用独立密码 | TCP + UDP |
| SS2022 AES | 2022-Blake3-AES-128-GCM、2022-Blake3-AES-256-GCM | 多客户端，共用入站服务端密钥，各自使用客户端密钥 | TCP + UDP |
| SS2022 ChaCha20 / 单密码模式 | 2022-Blake3-ChaCha20-Poly1305 或单密码配置 | 一个客户端 | TCP + UDP |
| VLESS + Reality | TCP + Vision | 多客户端，各自使用 UUID | TCP |
| SOCKS5 | 账号密码认证 | 多客户端，各自使用账号密码 | TCP |
| HTTP | 账号密码认证，支持 CONNECT | 多客户端，各自使用账号密码 | TCP |

SS2022 AES 多客户端的分享链接和出站 JSON 会自动组合 `服务端密钥:客户端密钥`。SOCKS5 / HTTP 提供 TCP 代理，协议本身不加密客户端到代理服务器的连接。

### 快速创建

1. 主菜单选择 **1**，选择入站协议。
2. 选择网络环境；普通公网 VPS 可直接回车，NAT 机器填写服务商已分配的公网端口。
3. 按提示选择是否使用连接域名；不使用域名时自动获取本机公网 IP。
4. 脚本自动选择端口、生成名称与凭据，创建入站和首个客户端。
5. 复制创建结果中的链接，在客户端中导入；客户端不支持链接导入时，可手动填写或使用出站 JSON。

普通公网环境会自动选择空闲端口；NAT 快速创建默认使用与公网端口相同的本机监听端口。Reality 会自动生成 UUID 和密钥，从候选伪装站点中选择并检查实际连接，无需为伪装站点购买域名或申请证书。

### 自定义创建

进入 **9 → 1**，先创建入站，再添加客户端：

1. 选择协议、入站名称，以及加密方式或 Reality 伪装域名。
2. 选择是否手动设置本机监听端口，跳过则自动选择空闲端口。
3. 选择公网连接端口是否与监听端口不同，需要时分别设置。
4. 选择是否使用连接域名；填写域名后，可继续选择是否设置 DDNS 更新方式。
5. 保存入站，再设置客户端名称和凭据。

在客户端名称提示中输入 `0`，可以保存入站后稍晚添加客户端。没有启用客户端的入站不会监听端口，但仍会保留已配置的端口供该入站使用。

SOCKS5 / HTTP 的自定义客户端需要填写账号和密码，密码输入时明文显示。两项均不能为空、不能包含控制字符，最长 255 字节；账号不能包含冒号，密码支持冒号、空格、`@`、`%` 等字符。

### 查看和管理节点

- **主菜单 2：** 选择入站，再选择客户端，查看连接信息、复制分享链接或导出单个出站 JSON；也可批量显示全部启用入站中启用客户端的链接。
- **主菜单 3：** 查看不含密码的总览，适合检查名称、端口和客户端数量。
- **主菜单 4：** 修改监听端口、公网地址、DDNS / NAT 映射信息，管理入站和客户端的开关、名称、添加及删除。

修改连接地址、端口或凭据后，请重新复制链接并导入客户端。这里导出的出站 JSON 用于连接该节点，可以加入客户端或 3x-ui 的 `outbounds` 数组；服务器自身使用的转发出口在主菜单 **5** 配置。

## NAT、域名与 DDNS

快速创建和修改连接地址时，可选择以下网络环境；自定义创建直接按需填写端口、域名和 DDNS 参数。

| 网络环境 | 选择 | 准备内容 |
| --- | --- | --- |
| 独立公网 / 固定 IP | 1 | 可自动获取公网 IP，或使用连接域名 |
| NAT / 端口映射 | 2 | 服务商或路由器已分配的公网端口，可选连接域名 |
| 动态公网 IP + DDNS | 3 | 可选 DDNS 域名 |
| NAT + 动态 IP + DDNS | 4 | 已分配的公网端口，可选 DDNS 域名 |

**端口映射：** NAT 机器须使用服务商或路由器分配的端口。公网连接端口与本机监听端口可以不同，可在自定义创建或入站管理中设置。脚本保存连接信息，上游端口映射仍需在服务商或路由器处配置；防火墙、安全组和映射的 TCP / UDP 类型应与入站协议对应。

**连接地址：** 不使用域名时自动获取本机出口公网 IP，优先 IPv4，失败后尝试 IPv6。服务商入站地址与出口地址不同时，使用已解析到入站地址的域名。动态 IP 环境使用纯 IP 链接时，IP 变化后需要重新设置连接地址并导入链接。

**DDNS：** 可以使用路由器或 ddns-go 等维护的现有域名，也可在 **9 → 3** 配置 Cloudflare / DuckDNS，每 5 分钟自动更新。Cloudflare Token 需要区域读取和 DNS 编辑权限，连接域名应设为“仅 DNS”。非 systemd 系统需要安装并启动 cron 执行定时更新。

**IPv4 / IPv6：** 系统启用 IPv6 时，节点默认使用双栈监听。具备可访问公网 IPv6 时，连接 IPv4 和 IPv6 使用相同端口与凭据，IPv6 链接使用 `[IPv6]:端口` 格式。

**NAT 多出口：** 默认配置使用 Cloudflare / Google 加密 DNS 获取真实地址，按可用网络优先 IPv4、回退 IPv6，适用于使用 Fake-IP 的出口工具。切换外部出口线路后可继续使用原节点，服务商线路和端口映射须保持可达。

Reality 的伪装域名与自己的连接 / DDNS 域名分别设置：前者用于 Reality 握手，后者用于客户端找到服务器。

## 服务器出站

进入主菜单 **5**，粘贴协议链接或原生 Xray JSON 导入出口。

| 导入格式 | 支持内容 |
| --- | --- |
| SS 链接 | `ss://`，包含 SS2022 |
| VLESS 链接 | `vless://` |
| SOCKS 链接 | `socks://`、`socks5://` |
| HTTP 代理链接 | `http://`、`https://` |
| 原生 Xray JSON | 单个出站对象、出站数组，或完整配置中的 `outbounds` 部分 |

多行 JSON 可直接粘贴，内容完整时自动识别；未自动识别时，单独输入一行 `结束` 提交。导入前显示隐藏凭据的预览，可以选择其中部分出口；标签冲突时自动分配新标签。完整 Xray 配置只导入出站部分，其他部分分别通过对应菜单设置。

**入站协议与出站协议独立。** SS 入站可以转发到 SS、SS2022、VLESS、VMess、Trojan、SOCKS、HTTP 等出口，也可以使用混合协议的均衡组。原生 JSON 支持已安装 Xray 内核接受的出站协议和参数；没有对应链接解析器或链接参数无法识别时，使用原生 JSON。

出站管理支持连接测试、改名、替换连接参数、启用 / 停用、导出和删除。替换连接参数保留出站标签，便于继续使用已有路由引用。完整导出包含凭据，请妥善保管。

## 路由规则

进入主菜单 **6**。规则从上往下匹配，命中第一条后使用对应出口；同一规则中的不同条件需要同时满足，未命中的流量使用默认出口。

| 条件 | 填写方式 |
| --- | --- |
| 来源入站 | 列表序号、标签或名称，多个用英文逗号分隔，留空表示所有入站 |
| 来源客户端 | 选择一个来源入站后限定客户端；唯一客户端自动选中，多个客户端继续选择 |
| 目标域名 | `domain:example.com`、`full:www.example.com`、`keyword:example`、`regexp:`、`geosite:` |
| 目标 IP | IPv4、IPv6、CIDR 网段或 `geoip:` |
| 目标端口 | `443`、`80,443`、`1000-2000` 等 |
| 网络类型 | `tcp`、`udp` 或 `tcp,udp` |
| 流量去向 | 直连、拦截、指定出站或负载均衡组 |

可选目标条件留空表示不限。SS / VLESS 可按可识别的客户端身份分流；SOCKS5 / HTTP 按入站分流。原生规则 JSON 还可设置源 IP、源端口、应用协议等 Xray 支持的条件。使用 GeoIP / GeoSite 前，需自行准备内核可读取的数据库；缺少所需文件时配置校验会拒绝应用。

### 将一个入站转发到指定出口

1. 在 **5** 导入并测试目标出站。
2. 在 **6 → 1** 添加规则，填写规则名称，选择来源入站，例如 `1`。
3. 按需限定客户端，目标域名、IP、端口等条件留空可匹配该来源的全部目标。
4. 流量去向选择 **3 · 指定出站**，再选择目标出站并保存。

指定出站可以直接使用，无需创建均衡组。向导中的目标端口是访问网站或服务的端口；要按节点监听端口区分流量，应选择对应的来源入站。

### 规则管理

支持编辑、启用 / 停用、改名、排序、复制、删除、JSON 导入导出及引用检查。默认出口可设为直连、拦截、指定出站或均衡组。

**6 → 7** 设置 `AsIs`、`IPIfNonMatch` 或 `IPOnDemand` 域名解析策略；**6 → 8** 按入站设置 HTTP / TLS / QUIC 嗅探，用于识别域名等信息。

## 负载均衡

先在主菜单 **5** 准备出口，再进入 **7** 创建均衡组。成员可以填写出站序号、标签或名称，多个用英文逗号分隔，支持不同协议的出站共同参与。

| 策略 | 行为 |
| --- | --- |
| 随机 `random` | 随机选择成员处理连接 |
| 轮询 `roundRobin` | 依次选择成员处理连接 |
| 最低延迟 `leastPing` | 通过健康探测选择延迟较低的可用成员 |

可以设置全部成员不可用时的回退出站；使用最低延迟策略或设置回退时，自动启用 Xray 健康探测。**7 → 3** 可调整探测 URL 和间隔，均衡组管理中可逐个测试成员连接。

创建后，到 **6** 将规则或默认出口指向该均衡组。Xray 均衡成员标签采用前缀匹配，配置校验会检查是否意外匹配到组外出口。

启用规则、默认出口和均衡组需要引用启用的目标；被引用的对象需要先解除引用再删除。出站、规则和均衡配置会先检查引用并通过内核校验，再应用到服务；运行中的服务重启生效，已停止的服务保持停止，应用失败时回滚。

## 服务、日志与排障

管理菜单退出后不常驻，流量由 Xray 内核处理；启用 DDNS 时使用系统定时任务。需要查看状态、启动 / 重启或诊断连接时，进入主菜单 **8**。

**日志默认关闭。** 排障时选择 **8 → 5** 开启，仅记录警告和错误，保存到 `/var/log/xray-ss.log`，不记录访问明细；**8 → 6** 关闭，**8 → 7** 清空本工具的历史日志。

```bash
sudo xnode status       # 查看服务状态
sudo xnode logs on      # 开启警告和错误日志
sudo xnode logs         # 查看日志
sudo xnode logs off     # 关闭日志
sudo xnode logs clear   # 清空本工具的历史日志
sudo xnode diagnose     # 诊断 Reality 连接
```

连接失败时，先核对协议、客户端凭据、连接地址、端口、防火墙和安全组，NAT 环境同时检查上游映射。Reality 诊断会检查服务、端口、密钥和伪装站点；伪装站点不兼容时，可更换站点。内核安装和版本选择位于 **9 → 2**。

## 常用命令

以下命令由 root 执行，普通用户可在前面加 `sudo`。

```bash
xnode                         # 打开主菜单
xnode add                     # 快速创建入站和客户端
xnode custom                  # 自定义创建入站，再添加客户端
xnode show                    # 按入站和客户端查看连接信息
xnode links                   # 批量显示启用客户端的链接
xnode list                    # 查看入站与客户端总览
xnode inbounds                # 入站和客户端管理
xnode clients                 # 选择入站，管理客户端
xnode outbounds               # 服务器出站设置
xnode routing                 # 路由规则和默认出口
xnode balancers               # 均衡组和健康探测
xnode outbound-import out.json # 从文件导入出站
xnode rule-import rules.json   # 从文件导入规则
xnode ddns                    # 配置 DDNS
xnode ddns-update             # 立即更新一次 DDNS
xnode check                   # 检查系统兼容性
```

文件导入命令中的文件名可以使用 `-`，表示从标准输入读取。

## 配置、备份与卸载

完整备份请保存整个 `/etc/xray-ss` 目录，其中包含连接凭据和可能存在的 DDNS Token。

| 文件 / 目录 | 内容 |
| --- | --- |
| `inbounds.json` | 入站、客户端、凭据和开关 |
| `network.json` | 服务器出站、规则、默认出口、均衡组及探测设置 |
| `config.json` | 生成后交给 Xray 使用的运行配置 |
| `node-hosts.json`、`node-meta.json` | 公网连接地址、端口映射和节点元数据 |
| `ddns.json` | 配置本机 DDNS 时保存的更新参数和凭据 |
| `backups/` | 配置备份 |

完整恢复时一并恢复相关配置文件。**6 → 9** 用于恢复网络配置备份，范围是出站、规则和均衡等网络设置，恢复前会检查它们与当前入站的引用关系。

完全卸载位于 **9 → 5**，按提示输入 `确认卸载`。需要保留节点时，先将完整备份复制到其他位置。
