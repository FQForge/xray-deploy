# Xray 中文节点管理工具

在 Linux VPS 上创建 **SS、SS2022、VLESS + Reality、SOCKS5、HTTP** 节点，提供中文菜单，支持普通公网、NAT 端口映射和动态 IP / DDNS。

## 安装

登录 VPS 后执行：

```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/FQForge/xray-deploy/main/install-xray-ss.sh)"
```

安装后自动打开菜单。以后输入 `xnode` 即可；普通用户使用 `sudo xnode`。首次创建会自动安装 Xray 内核和所需依赖。

如果提示找不到 `curl`，请先安装它；Debian / Ubuntu 可执行 `apt-get update && apt-get install -y curl`。没有 root / sudo 权限时，请切换到 root 用户。

## 第一次创建节点

1. 主菜单选择 **1 · 快速创建节点**。
2. 选择 **SS、SS2022、VLESS + Reality、SOCKS5 或 HTTP**，客户端需支持相应协议。原有三种协议的序号保持不变，**4 为 SOCKS5，5 为 HTTP**。
3. 普通 VPS 的网络环境直接回车，使用 **1 · 独立公网 / 固定 IP**。
4. 询问是否使用域名时，直接回车自动获取本机公网 IP；选择使用域名时再填写域名，域名留空也会自动获取 IP。
5. 创建成功后，复制完整的 `ss://` 或 `vless://` 链接，在客户端选择“从剪贴板导入”并启用代理。SOCKS5 / HTTP 可使用 `socks5://` / `http://` 链接，客户端不支持导入时手动填写连接信息。

快速创建时，名称、端口、密码和密钥会自动生成，SOCKS5 / HTTP 也会自动生成账号。Reality 使用 **TCP + Vision**，从 **10 个已实测通过的非 Cloudflare 域名**中随机选择，并在创建前检查真实连接；无需自己购买域名或申请证书。

**SOCKS5 / HTTP：** 在 **6 · 高级设置 → 1 · 自定义创建节点** 中选择这两种协议时，需自己输入账号和密码，密码输入时明文显示。两项均不能为空、不能包含控制字符，最长 255 字节，账号不能包含冒号；密码可以包含冒号等特殊字符。快速创建无需输入账号密码。创建后可在连接信息中查看完整账号密码，使用 `socks5://` / `http://` 链接、手动填写或导出 Xray 出站 JSON 配置客户端。

SOCKS5 / HTTP 节点使用账号密码认证，提供 **TCP 代理**；HTTP 支持通过 CONNECT 访问 HTTPS。这两种协议本身不加密客户端到代理的连接。

**记得放行节点端口：** 在 VPS 防火墙和服务商安全组中，Reality / SOCKS5 / HTTP 放行 **TCP**；SS / SS2022 放行 **TCP + UDP**。具体端口会在创建结果中显示。

## NAT 或动态 IP 怎么选

| 你的网络 | 创建时选择 | 需要准备 |
| --- | --- | --- |
| 普通公网 VPS | 1 · 独立公网 / 固定 IP | 通常直接回车即可 |
| NAT 服务器 / 路由器端口映射 | 2 · NAT / 端口映射 | 已分配的公网端口，可选连接域名 |
| IP 会变化 | 3 · 动态公网 IP + DDNS | 可选 DDNS 域名；不使用域名则自动获取当前公网 IP |
| 同时是 NAT 和动态 IP | 4 · NAT + 动态 IP + DDNS | 已分配的公网端口，可选 DDNS 域名 |

**连接地址：** SS、SS2022、Reality、SOCKS5、HTTP 的快速创建、自定义创建和修改地址共用相同流程，所有网络环境都会询问是否使用域名。不使用域名时自动获取本机公网 IP，优先 IPv4、失败后尝试 IPv6；自动检测失败会结束本次操作，不再要求手动输入 IP。

**NAT：** 创建时填写已分配的公网端口，再选择是否使用域名；本机默认监听相同端口，不再额外询问。若上游映射使用不同的本机端口，创建后到 **管理节点 → 修改本机监听端口** 调整；修改已有节点的公网地址或映射时保留原本机端口。自动获取的是本机出口公网 IP；服务商入站地址与出口地址不同时，请使用已解析到入站地址的域名。脚本不会替你创建上游映射；没有分配入站端口的 NAT 不能直接连接。

**DDNS：** 可以使用已有 DDNS，也可在向导中配置 Cloudflare 或 DuckDNS 自动更新。Cloudflare Token 需有区域读取和 DNS 编辑权限，连接域名使用“仅 DNS”。非 systemd 系统需安装并启动 cron，才能每 5 分钟自动更新。

动态 IP 环境选择不使用域名时，链接使用本次检测到的 IP；公网 IP 变化后需重新修改连接地址并导入链接。

Reality 的伪装域名和自己的连接 / DDNS 域名是两个地址，按向导分别设置即可。

**NAT 多出口工具：** 搭建时会持久配置 Cloudflare / Google 加密 DNS，获取真实地址，按可用网络优先使用 IPv4、回退 IPv6，兼容 LazyCat 等使用 Fake-IP 的出口工具。搭建完成后，直接在 `proxy` 等出口工具中切换线路即可，无须重新运行 `xnode`、重建节点或手动重启 Xray。服务商线路及 TCP / UDP 映射仍需正常。

**IPv4 / IPv6：** 系统启用 IPv6 时，同一节点默认同时监听 IPv4 和 IPv6。服务器具备可访问的公网 IPv6 时，客户端可以把服务器地址从 IPv4 改成 IPv6，端口和凭据保持相同；IPv6 分享链接会使用 `[IPv6]:端口` 格式。出站优先 IPv4 不限制 IPv6 接入或访问 IPv6 目标。

已有安装更新到此版本时，会自动备份并补齐缺省 DNS 设置，并将旧版默认日志改为关闭；已有自定义 DNS、出站解析策略和显式开启的日志设置会保留。升级配置时，运行中的 Xray 会重启一次，失败则回滚；已停止的服务保持停止。后续切换出口不需要再次执行更新。

## 常用操作

| 操作 | 菜单位置 |
| --- | --- |
| 复制已有节点链接 | 主菜单 **2** |
| 修改地址、端口，导出 3x-ui 出站 JSON，删除节点 | 主菜单 **4** |
| 查看服务状态、重启、日志、Reality 诊断 | 主菜单 **5** |
| 自定义名称、加密方式、Reality 域名或代理账号密码 | **6 → 1** |
| 切换内核 / 配置 DDNS / 检测系统 / 完全卸载 | **6 → 2 / 3 / 4 / 5** |

菜单输入 **0** 返回或退出。修改连接信息后，请重新复制链接导入客户端。导出的 3x-ui JSON 是单个出站对象，应加入 `outbounds` 数组。

## 资源占用和日志开关

VPS / NAT 安装后只常驻 Xray 内核，管理菜单退出后不占用内存；启用 DDNS 时使用系统定时任务。安装包和校验文件用完即删除，只安装所需的内核文件，不额外安装管理面板或 GeoIP / GeoSite 数据库。已有内核和节点备份保留，便于切换和恢复。

**Xray 日志默认关闭**，不记录访问、DNS 查询或错误日志，服务启动输出也不会持续写入文件或系统日志。需要排障时，在主菜单 **5 · 服务管理** 中选择 **5 · 开启日志**，结束后选择 **6 · 关闭日志**；**7** 可清空本工具的历史日志。也可以使用：

```bash
sudo xnode logs on       # 开启，仅记录 warning / error
sudo xnode logs          # 查看已记录的日志
sudo xnode logs off      # 关闭，保留历史日志
sudo xnode logs clear    # 清空本工具的历史日志，释放空间
```

开启后的日志保存在 `/var/log/xray-ss.log`，不记录访问明细。日志开关会保留节点和网络设置；正在运行的服务会重启以生效，已停止的服务保持停止，设置失败则回滚。重新运行安装命令会保留已选择的日志开关。关闭后历史日志不会继续增长，可按需清空；旧版已写入系统日志的内容仍由系统管理。Reality 诊断仍可使用，临时诊断日志在检查结束后自动删除。

## 连接失败、更新和备份

先确认客户端协议正确、公网端口已放行；NAT 还要确认映射有效。Reality 可运行：

```bash
sudo xnode diagnose
```

**更新工具：** 重新执行上面的安装命令，保留现有节点。安装默认内核并诊断 Reality 可执行：

```bash
sudo xnode install-default
sudo xnode diagnose
```

默认内核为 **v26.6.1**；首次创建自动安装该版本，创建 Reality 时也使用该版本作为最低版本，已安装的较新内核继续使用。安装包下载或 SHA256 校验失败时立即停止安装。

v26.6.1 的 Reality 对较大的 TLS 握手记录存在兼容性限制。自动选择伪装站点时会逐个验证实际隧道，失败后尝试下一项；自定义域名未通过时，请更换域名重新创建，或在高级设置中手动选择兼容的较新官方内核。

**备份：** 保存 `/etc/xray-ss`。**卸载：** 选择 **6 → 5**，按提示输入 `确认卸载`。

## 系统支持

推荐使用 **Ubuntu 22.04 / 24.04 或 Debian 12 / 13**。脚本也适配 Alpine、Rocky / AlmaLinux / Fedora、openSUSE、Arch、Void、Gentoo 和 OpenWrt 的常见包管理与服务方式，但不能保证所有历史版本、定制固件和 CPU 都可用。

本次使用默认内核 **v26.6.1** 重新验证 Ubuntu 22.04 本机，以及 Ubuntu 20.04 / 24.04、Debian 12 / 13、Alpine 3.22、Rocky 9 的 amd64 隔离环境；三种协议 HTTPS、Reality 诊断和节点管理测试全部通过。

Ubuntu 22.04 还通过了 7 种 SS / SS2022 加密的 TCP / UDP、10 个 Reality 候选域名、首次创建、一键更新保留节点及下载校验失败保护测试。隔离环境共用本机内核，其他内核和 CPU 架构未逐一实测。

新增的 SOCKS5 / HTTP 已在 **Debian 12、512 MB 内存的 NAT LXC VPS** 上，使用 **v26.6.1、v26.10.21** 两版官方内核完成测试：快速创建自动生成账号密码、高级设置手动输入及密码明文回显、空值和特殊字符校验、IPv4 / IPv6、HTTP / HTTPS 代理、错误账号密码拒绝、分享链接和出站 JSON 均通过；原有 7 种 SS / SS2022 加密的 TCP / UDP 及 Reality HTTPS 回归也通过。

同一台 VPS 还通过了外部客户端连接 **公网 IPv4 NAT 实际映射和公网 IPv6** 的五种协议测试，包括 SS / SS2022 UDP。节点管理、地址和端口修改、日志开关、内核切换与切回、更新保留节点、失败回滚、下载与校验失败保护、完全卸载、重新安装及节点备份恢复均通过。临时配置文件使用 `.json` 后缀，兼容新版内核的配置加载要求。

Cloudflare / DuckDNS 的请求、成功和失败响应处理通过本地 HTTP 测试服务验证，systemd DDNS 定时器已实际创建、启用和触发；未修改真实公网 DNS 记录。systemd 开机自启配置已验证，未实际重启容器。其他网络环境、内核和 CPU 架构仍需在目标机器上验证。

支持 systemd、OpenRC、SysVinit、runit 和 procd；未识别到服务管理器时使用手动模式，**手动模式不支持开机自启**。CPU 必须有对应的 Xray 官方 Linux 安装包，系统软件源应可用，Reality 需要 curl 支持 TLS 1.3。

安装后运行 `xnode check` 查看当前系统的检查结果；检查通过不等于所有旧内核和网络环境都已实测。
